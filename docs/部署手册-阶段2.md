# 部署手册｜阶段2：Links 信息分享站上 K8s

> 项目：K8s 云原生平台
> 内容：苹果风信息分享站（轻量动态 + 外链分享，管理员后台发布），与宿主机旧博客共存
> 更新日期：2026-08-25

---

## 一、架构

```
浏览器 → Ingress(https://share.k8s.local:32443)
         → ingress-nginx(NodePort 32080 http / 32443 https)
         → links-nginx (Deployment, 静态层+反代, 配置由 ConfigMap 注入)
         → links-app   (Deployment, Node+EJS, HPA 扩缩容)
         → links-mysql (StatefulSet, LocalPV 持久化)
         → links-redis (StatefulSet, LocalPV, 存 session)
```

- 命名空间：`links-ns`（与旧博客宿主机 docker 完全隔离）
- 与旧博客共存：旧博客走宿主机 8080 + zqqqz.xyz，新站走集群 Ingress，互不干扰

## 五、部署步骤

```bash
# 1) hosts 解析
echo "192.168.80.133 share.k8s.local" | sudo tee -a /etc/hosts

# 2) 安装
helm install links /home/zqq/k8s/helm-charts/links-chart

# 3) HTTPS 证书（用 Harbor 的 CA 签发 share.k8s.local 证书）
kubectl -n links-ns create secret tls links-tls \
  --cert=/home/zqq/k8s/tls/share.k8s.local.crt \
  --key=/home/zqq/k8s/tls/share.k8s.local.key

# 4) Ingress 加 TLS 后升级
helm upgrade links /home/zqq/k8s/helm-charts/links-chart

# 5) 验证
curl -s https://share.k8s.local:32443/health   # {"status":"ok","db":true,"redis":true}
```

访问：`https://share.k8s.local:32443`（浏览器需信任 Harbor-CA 或点继续访问）
管理员：`admin` / 密码在 values.yaml secrets.adminPassword（演示环境）

## 七、踩坑记录（阶段2）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | app CrashLoopBackOff：`connectRedis is not a function` | connect-redis v8 改为命名导出 `{ RedisStore }`，v7 才是函数导出 | 改 `const { RedisStore } = require('connect-redis')` |
| 2 | nginx CrashLoopBackOff | liveness 探活 /health 反代到挂掉的 app 得 502 被判不健康 | 修好 app + nginx liveness 改 tcpSocket |
| 3 | 新版本 ImagePullBackOff | `cd - docker push` 少写 `&&`，镜像没推上 Harbor | 检查本地镜像 → 补 push |
| 4 | 浏览器 SSL_ERROR_RX_RECORD_TOO_LONG | 浏览器 HTTPS-Only 模式把 http 强升 https，32080 是明文端口 | 配 ingress TLS + 走 32443，或关浏览器强制 HTTPS |
| 5 | metrics-server Metrics API not available | kubeadm 自签证书环境需 --kubelet-insecure-tls | components.yaml 加该参数 |
| 6 | 缩容有延迟 | HPA 默认 stabilization window 5 分钟（防抖动） | 属正常机制，等待即可 |

# 部署手册｜双节点扩展：Worker 接入与镜像私有化

> 项目：K8s 云原生平台
> 内容：单节点 → 双节点（kubeadm join）、跨节点网络、镜像全量私有化
> 更新日期：2026-08-26

---

## 一、架构变更

```
之前：zqq(master, 7.7G)  ← 单节点，控制面+业务+基础设施全挤一起
现在：
  zqq        master/control-plane  7.7G  控制面 + Harbor + Jenkins + 监控(后续)
  k8s-node01 worker                3G    kube-proxy + flannel + 业务(可调度)
```

- Worker：2C-3G，Ubuntu 22.04，静态 IP 192.168.80.11
- 动机：宿主 16G 内存装不下 3 节点，但业务/监控需要分散；双节点兼顾资源与多节点简历价值

## 二、Worker 接入流程

### 1. 基础配置（VMware 新建 Ubuntu 22.04）

```bash
# 静态 IP + 主机名 + sudo 免密 + hosts（注意用 -t 分配终端才能交互输密码）
ssh -t zqq@192.168.80.11 "sudo hostnamectl set-hostname k8s-node01 && echo 'zqq ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/zqq >/dev/null && sudo chmod 440 /etc/sudoers.d/zqq"
```

### 2. Ansible 初始化（复用 init-cluster.yml）

```bash
# 更新 inventory.ini：nodes 组加入 k8s-node01
ansible-playbook -i inventory.ini init-cluster.yml
# node01: 关swap/内核参数/containerd(cgroup v2+阿里云沙箱)/kubeadm/kubelet
```

### 3. kubeadm join

```bash
# master 上生成 join 命令（旧 token 24h 过期）
kubeadm token create --print-join-command
# worker 上执行（⚠️ join 不支持 --image-repository 参数）
sudo kubeadm join 192.168.80.133:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash>
```

### 4. Worker 的 Harbor 访问配置（hosts + CA + docker.io 加速）

```bash
# worker 上（脚本方式，避免引号问题）
echo '192.168.80.133 harbor.k8s.local' >> /etc/hosts
echo '192.168.80.133 share.k8s.local' >> /etc/hosts
cp /tmp/harbor-ca.crt /usr/local/share/ca-certificates/harbor-ca.crt
update-ca-certificates
systemctl restart containerd
```

### 5. 验证

```bash
kubectl get nodes          # 两台 Ready
# 跨节点网络：worker 上 Pod 访问 master 服务
kubectl run net-test --image=harbor.k8s.local:30443/blog-project/busybox:latest --restart=Never \
  --overrides='{"spec":{"nodeSelector":{"kubernetes.io/hostname":"k8s-node01"},"imagePullSecrets":[{"name":"harbor-secret"}]}}' \
  --command -- sh -c "wget -qO- http://links-nginx.links-ns.svc:80/health"
```

## 三、镜像全量私有化（关键决策）

**背景**：worker 拉 `ghcr.io/flannel` 镜像 TLS 超时（CDN 被墙）；containerd 2.2 的 hosts.toml mirror 配置不生效（与 Harbor 证书那次同一问题）。

**决策**：集群内全部镜像改走 Harbor，不依赖外网。

| 镜像 | 原地址 | Harbor 地址 |
|---|---|---|
| flannel | ghcr.io/flannel-io/flannel:v0.28.9 | blog-project/flannel:v0.28.9 |
| flannel-cni-plugin | ghcr.io/flannel-io/flannel-cni-plugin:v1.9.1-flannel3 | blog-project/flannel-cni-plugin:v1.9.1 |
| mysql | mysql:8.0.36 | blog-project/mysql:8.0.36 |
| redis | redis:7.2.4-alpine | blog-project/redis:7.2.4 |
| busybox | busybox:latest | blog-project/busybox:latest |
| jenkins / agent | docker.io/jenkins* | blog-project/jenkins* |
| links-app / nginx | 自定义 | blog-project/links-* |

**私有化后的必配项（两个都容易漏）**：
1. **imagePullSecrets**：私有仓库拉取凭据，Deployment **和 StatefulSet** 都要（flannel DaemonSet 也踩过坑）
2. **镜像版本同步**：helm `--set` 临时覆盖后，手动 upgrade 会回退 values.yaml 里的旧版本

## 四、踩坑记录（双节点）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | sudoers 语法错误导致 worker sudo 全挂 | ssh 远程命令引号被 shell 拆分，写入格式错误的 sudoers | **VMware recovery mode** 修复：`mount -o remount,rw /` + 重写文件。教训：远程复杂命令用脚本文件传输 |
| 2 | join 预检 `ip_forward` 不是 1 | ansible 的 sysctl handler 在 node 上未触发 | worker 手动 `sysctl --system` 应用 |
| 3 | join 报 `unknown flag: --image-repository` | 该参数仅 kubeadm init 支持 | 去掉，join 本身不拉镜像 |
| 4 | flannel Init:ImagePullBackOff | 新版本 flannel 镜像在 ghcr.io（CDN 被墙） | 镜像推到 Harbor + DaemonSet 改地址 |
| 5 | 拉 Harbor 镜像 `no basic auth` | 私有仓库缺 imagePullSecrets | flannel DaemonSet、mysql/redis StatefulSet 补凭据 |
| 6 | worker 解析不了 harbor.k8s.local | hosts 没配 + CA 未信任 | 脚本一次性补齐 + 重启 containerd |
| 7 | helm upgrade 后 app 回退旧镜像 CrashLoop | values.yaml 的 images 还是 v1，--set 覆盖是临时的 | values.yaml 同步最新版本号 |

## 二、阶段0：kubeadm 单节点集群

### 0.1 静态 IP 配置

> ⚠️ 必须做：DHCP 重启会变 IP，kubeadm 证书绑定 IP，变了集群就废

```bash
# 禁用 cloud-init 接管网络（防止重启后配置被覆盖）
echo "network: {config: disabled}" | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg

# 新建静态 IP 配置（99 前缀优先级高于 50-cloud-init.yaml）
sudo tee /etc/netplan/99-static.yaml <<'EOF'
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: false
      addresses: [192.168.80.133/24]
      routes: [{to: default, via: 192.168.80.2}]
      nameservers: {addresses: [223.5.5.5, 114.114.114.114]}
EOF
sudo chmod 600 /etc/netplan/99-static.yaml
sudo netplan apply

# 验证：结尾应为 static（不是 dynamic），能 ping 通外网
ip -4 addr show ens33 | grep inet
ping -c1 baidu.com
```

### 0.2 内核参数（K8s 前置要求）

```bash
cat <<'EOF' | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter

cat <<'EOF' | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system
sysctl net.ipv4.ip_forward   # 期望输出 1
```

### 0.3 containerd 配置（⚠️ containerd 2.x 与老教程差异大）

containerd 2.2.1 生成的是 `version = 3` 格式配置，**沙箱镜像键名是 `sandbox` 不是 `sandbox_image`**，默认镜像为 `pause:3.10.1`（registry.k8s.io，国内拉不到）：

```bash
sudo mkdir -p /etc/containerd    # 注意：目录可能不存在，需先建
containerd config default | sudo tee /etc/containerd/config.toml > /dev/null

# cgroup v2 必须 systemd 驱动（kubelet 默认 systemd）
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

# 沙箱镜像换阿里云（2.x 的键名是 sandbox，位于 pinned_images 段）
sudo sed -i "s#sandbox = 'registry.k8s.io/pause:3.10.1'#sandbox = 'registry.aliyuncs.com/google_containers/pause:3.10'#" /etc/containerd/config.toml

sudo systemctl restart containerd
# 验证
grep -n "sandbox =" /etc/containerd/config.toml
```

### 0.4 安装 kubeadm / kubelet / kubectl（阿里云源）

```bash
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://mirrors.aliyun.com/kubernetes/apt/doc/apt-key.gpg | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes.gpg] https://mirrors.aliyun.com/kubernetes/apt/ kubernetes-xenial main" | sudo tee /etc/apt/sources.list.d/kubernetes.list
sudo apt update && sudo apt install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl   # 防止自动升级破坏集群
```

### 0.5 kubeadm init（单节点）

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.80.133 \
  --pod-network-cidr=10.244.0.0/16 \
  --image-repository=registry.aliyuncs.com/google_containers
```

> 成功标志：`Your Kubernetes control-plane has initialized successfully!`
> ⚠️ `[kubelet-check] Initial timeout of 40s passed.` 只是中间步骤，**不要在此按 Ctrl+C**，后面还有生成 kubeconfig、装 CoreDNS

### 0.6 配置 kubectl

```bash
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
echo 'source <(kubectl completion bash)' >> ~/.bashrc
kubectl get nodes   # 此刻 NotReady 正常（还没装 CNI）
```

### 0.7 去掉 master 污点（单节点必须）

```bash
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
```

### 0.8 安装 flannel CNI（比 Calico 省内存，单节点够用）

> ⚠️ raw.githubusercontent.com 在国内超时，必须用 github releases 的完整 URL，先下载再 apply

```bash
curl -L -o /tmp/kube-flannel.yml https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
kubectl apply -f /tmp/kube-flannel.yml
kubectl get pods -A -w      # 等 kube-flannel-ds 变 Running
kubectl get nodes           # zqq 变 Ready
```

### 0.9 冒烟测试（验证调度 → 拉镜像 → Pod → Service → DNS 全链路）

```bash
kubectl create deployment nginx-test --image=nginx:latest
kubectl expose deployment nginx-test --port=80
kubectl get pods -o wide      # 等 Running，Pod 拿到 10.244.x.x 网段 IP
kubectl get svc               # 记下 CLUSTER-IP
kubectl run test-curl --rm -it --image=busybox:latest --restart=Never -- sh -c "wget -qO- http://nginx-test:80 | head -3"
# 期望输出 nginx 欢迎页 HTML，即 Service DNS 解析 + 跨 Pod 通信 OK
```

## 三、阶段1：Harbor 私有镜像仓库

### 1.1 安装 Helm + 本地存储（local-path-provisioner）

```bash
# Helm（国内 get.helm.sh 可访问）
curl -fsSL -o /tmp/helm.tar.gz https://get.helm.sh/helm-v3.16.4-linux-amd64.tar.gz
tar -zxvf /tmp/helm.tar.gz -C /tmp
sudo mv /tmp/linux-amd64/helm /usr/local/bin/helm
helm version

# local-path 动态存储（官方 manifest 无 release 资产，需从 api.github.com 拉源码，已存仓库 storage/ 目录）
kubectl apply -f storage/local-path-provisioner.yaml
kubectl get storageclass        # local-path / rancher.io/local-path / WaitForFirstConsumer
```

> 说明：local-path 会把 PV 数据放在节点 `/opt/local-path-provisioner`，reclaimPolicy 为 Delete

### 1.2 Harbor helm 仓库 + 证书生成

```bash
helm repo add harbor https://helm.goharbor.io
helm repo update

# 生成自签名 CA + 服务器证书（脚本在 harbor/gen-certs.sh，SAN 含域名和 IP）
bash harbor/gen-certs.sh

# hosts 解析
echo "192.168.80.133 harbor.k8s.local" | sudo tee -a /etc/hosts
```

### 1.3 创建 Secret + 安装

```bash
kubectl create ns harbor
kubectl -n harbor create secret tls harbor-tls \
  --cert=/home/zqq/k8s/harbor/certs/harbor.k8s.local.crt \
  --key=/home/zqq/k8s/harbor/certs/harbor.k8s.local.key
kubectl -n harbor create secret generic harbor-ca \
  --from-file=ca.crt=/home/zqq/k8s/harbor/certs/ca.crt

helm install harbor harbor/harbor -f harbor/values.yaml -n harbor
kubectl -n harbor get pods -w    # 等全部 Running（约3-5分钟）
```

**values.yaml 关键点**（完整文件在 `harbor/values.yaml`）：
- `expose.type: nodePort`，HTTP 30080 / HTTPS 30443
- `expose.tls.certSource: secret`（用我们自签的证书）
- `registry.relativeurls: true`（**nodePort 部署必须开**，否则 docker push 307 跳内部地址失败）
- `trivy.enabled: false`（需访问 GitHub 下漏洞库，国内必挂，且吃资源）
- 各组件配了内存 limits（7.7G 机器要精打细算）
- 存储全部走 `local-path` StorageClass

验证门户：`curl -sk https://harbor.k8s.local:30443/api/v2.0/ping` → `Pong`

### 1.4 证书信任配置（Docker push 侧 + containerd 拉取侧）

```bash
# Docker 信任（push 用）：目录名 = 域名:端口
sudo mkdir -p /etc/docker/certs.d/harbor.k8s.local:30443
sudo cp /home/zqq/k8s/harbor/certs/ca.crt /etc/docker/certs.d/harbor.k8s.local:30443/ca.crt

# containerd 信任（k8s 拉取用）
# 方式一（推荐，最可靠）：CA 加入系统信任库，containerd 默认走系统 CA 池
sudo cp /home/zqq/k8s/harbor/certs/ca.crt /usr/local/share/ca-certificates/harbor-ca.crt
sudo update-ca-certificates      # 注意文件名必须以 .crt 结尾，否则不生效
sudo systemctl restart containerd

# 方式二（备用）：hosts.toml 每仓库配置
# ⚠️ 实测 containerd 2.2.1 未生效（仍报 x509 unknown authority），故以方式一为准
# sudo mkdir -p /etc/containerd/certs.d/harbor.k8s.local:30443
# sudo cp .../ca.crt /etc/containerd/certs.d/harbor.k8s.local:30443/ca.crt
# sudo tee /etc/containerd/certs.d/harbor.k8s.local:30443/hosts.toml <<'EOF'
# server = "https://harbor.k8s.local:30443"
# [host."https://harbor.k8s.local:30443"]
#   ca = "/etc/containerd/certs.d/harbor.k8s.local:30443/ca.crt"
# EOF

# 验证系统信任生效（不带 -k 能通即 OK）
curl https://harbor.k8s.local:30443/api/v2.0/ping
```

### 1.5 推送 + 拉取闭环验证

```bash
# 登录 + 创建私有项目
docker login harbor.k8s.local:30443 -u admin -p Harbor12345
curl -sk -u admin:Harbor12345 -X POST https://harbor.k8s.local:30443/api/v2.0/projects \
  -H "Content-Type: application/json" \
  -d '{"project_name":"blog-project","public":false}'

# 推送测试镜像（注意：docker 镜像库和 containerd 是独立的，先 docker pull）
docker pull alpine:3.20
docker tag alpine:3.20 harbor.k8s.local:30443/blog-project/alpine:v1
docker push harbor.k8s.local:30443/blog-project/alpine:v1

# k8s 私有仓库拉取（需要 imagePullSecrets，用 YAML 而非 kubectl run --image-pull-secrets，1.28 已移除该参数）
kubectl create secret docker-registry harbor-secret \
  --docker-server=harbor.k8s.local:30443 \
  --docker-username=admin \
  --docker-password=Harbor12345

kubectl apply -f harbor/harbor-test2.yaml   # 见下
kubectl get pod harbor-test2 -w             # Running 即闭环成功
```

harbor-test2.yaml：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: harbor-test2
spec:
  containers:
    - name: alpine
      image: harbor.k8s.local:30443/blog-project/alpine:v1
      command: ["sleep", "3600"]
  imagePullSecrets:
    - name: harbor-secret
```

验证 containerd 真实发生拉取（非本地缓存命中）：

```bash
journalctl -u containerd --no-pager -n 30 | grep -iE 'PullImage|Pulled image'
# 期望看到 PullImage "harbor.k8s.local:30443/blog-project/alpine:v1" + Pulled image ...
```

## 四、踩坑记录（全部亲历，可作故障复盘素材）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | `containerd config default` 报 No such file | /etc/containerd 目录不存在（containerd 随 Docker 安装） | `sudo mkdir -p /etc/containerd` |
| 2 | 改了 `sandbox_image` 没效果 | containerd 2.2 配置结构变化：键名是 `sandbox`，默认 pause:3.10.1 | sed 改 `sandbox = 'registry.aliyuncs.com/google_containers/pause:3.10'` |
| 3 | kubeadm init 后 etcd/apiserver 崩溃循环 | kubelet 配置指向 192.168.80.33（init 时 DHCP 给的 IP），后静态 IP 变 .133，证书与配置错位 | `kubeadm reset -f` 后以正确 IP 重新 init |
| 4 | init 中途 Ctrl+C | 把 `[kubelet-check]` 误判为卡死 | reset 重来；kubelet-check 通过后还要生成 kubeconfig，耐心等成功提示 |
| 5 | netplan YAML 反复报错 | 手动复制 heredoc 丢了冒号/缩进 | 改为脚本文件执行（setup-netplan.sh） |
| 6 | apt-mark hold 失败 | unattended-upgrade 后台占 dpkg 锁 | 等 1-2 分钟重试即可 |
| 7 | 误装两套 Harbor（default + harbor 命名空间） | helm install 漏了 `-n` 和 `-f` 参数 | `helm uninstall harbor -n default` + 清理残留 PVC |
| 8 | `kubectl run --image-pull-secrets` 报未知参数 | kubectl 1.28 已移除该参数 | 改用 YAML 清单写 imagePullSecrets |
| 9 | containerd 拉 Harbor 报 `x509 unknown authority` | hosts.toml 的 ca 配置在 containerd 2.2.1 未生效 | CA 加入系统信任库 + `update-ca-certificates` + 重启 containerd |
| 10 | nginx 测试 Pod 秒起"假成功" | containerd 2.x 镜像按内容摘要匹配，之前冒烟测试的 nginx:latest 内容已在本地，未真正走 Harbor 拉取 | 用集群从未用过的 alpine 重新验证，日志确认 PullImage |
| 11 | `update-ca-certificates` 显示 0 added | cp 目标文件名拼错（多字符），必须以 `.crt` 结尾 | 修正文件名后重跑 |

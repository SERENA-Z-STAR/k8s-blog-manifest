# 部署手册｜阶段5：监控告警体系（Prometheus + Grafana + Loki）

> 项目：K8s 云原生平台
> 内容：监控指标、日志收集、告警通知全链路
> 更新日期：2026-08-26

---

## 一、架构

```
业务/系统指标                 容器日志
  node-exporter(每节点)  ─┐
  kube-state-metrics ─────┤→ Prometheus ─→ Grafana(可视化, 32001)
  apiserver/coredns/... ──┘     │ 规则评估
                                ↓
                           Alertmanager ──→ webhook-receiver(模拟企业微信)
  Pod 日志 ── promtail(DaemonSet) ──→ Loki(单实例) ──→ Grafana(日志查询)
```

- 命名空间：monitoring
- 调度策略：Prometheus/Grafana/Alertmanager/ksm/operator/Loki → **worker**；node-exporter/promtail → **全节点**
- 存储：local-path（Prometheus 5G / Grafana 2G / Alertmanager 2G / Loki 5G）

## 三、部署记录

### 1. kube-prometheus-stack（监控指标 + 告警）

```bash
helm install monitoring prometheus-community/kube-prometheus-stack \
  -f monitoring/kube-prometheus-stack-values.yaml -n monitoring --create-namespace
```

- **249 条告警规则**自动加载（Pod 崩溃循环/Deployment 副本丢失/节点内存/CPU 等）
- 资源配额收紧（单节点内存有限），node-exporter DaemonSet 全节点

### 2. Loki + Promtail（日志收集）

```bash
helm install loki grafana/loki -f monitoring/loki-values.yaml -n monitoring
helm install promtail grafana/promtail -f monitoring/promtail-values.yaml -n monitoring
```

- Loki **SingleBinary 模式**（deploymentMode: SingleBinary，7.x 必须显式指定）
- Promtail DaemonSet 采集全节点容器日志 → `http://loki:3100/loki/api/v1/push`

### 3. Alertmanager Webhook（模拟企业微信告警）

- webhook-receiver：python 简易接收端（monitoring/webhook-receiver/），接收并打印告警 JSON
- Alertmanager config：所有告警路由到 `http://webhook-receiver.monitoring.svc:8080/`
- 企业微信场景：把 receiver URL 换成 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<机器人key>` 即可

## 五、踩坑记录（阶段5）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | operator 镜像 ContainerCreating 卡死 | quay.io 国内拉取超时 | 镜像推 Harbor + set image |
| 2 | operator CrashLoop `open /cert/cert` | 关闭 admissionWebhooks 后 chart 仍挂载 tls-secret 且为空 | 手动生成自签证书填充 secret |
| 3 | helm upgrade 后 NodePort 丢失 | kubectl patch 的 NodePort 被 chart 默认值覆盖 | service type/nodePort 写进 values 固化 |
| 4 | worker 磁盘 DiskPressure | 新 VM 只分了 20G（根分区 10G） | VMware 扩盘 40G + growpart/LVM 扩展 |
| 5 | node-exporter 9100 冲突 | 旧博客 docker node_exporter 占宿主 9100（hostNetwork） | 停用旧博客监控组件，K8s 接管 |
| 6 | promtail 配置不生效 | chart 顶层键是 `config`（不是 `promtail.config`）；重复 kubernetes-pods job | 修正键路径，去掉自定义 scrape |
| 7 | loki 主 pod 没创建 / 组件混乱 | chart 7.x 需显式 `deploymentMode: SingleBinary`；缓存组件开关键在顶层 | 重写 values |
| 8 | 告警规则 MySQL 不可用 | kube-prometheus-stack 不含 MySQL 探测 | 待补（mysqld-exporter 或自定义规则） |

## 六、已知限制与遗留

1. **kube-controller-manager/scheduler/etcd/kube-proxy metrics down**：kubeadm 默认控制面 metrics 绑 127.0.0.1，Prometheus 抓不到（需改 bind-address，风险高，学习环境接受）
3. **MySQL 不可用告警**：待部署 mysqld-exporter 或自定义探活规则
4. 旧博客（宿主机 docker）监控组件已停用，由 K8s 监控栈接管
